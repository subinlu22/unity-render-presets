# 포트폴리오 노트: Unity Look Preset Tool for cafeSim

> "기능은 그대로, 보이는 현실만 바꾼다. 사진 한 장으로."

## 1. 무엇을 만들었나
웹 커피머신 학습 시뮬레이터(cafeSim)는 결제·추출·키오스크 같은 **동작은 실제 장비와 같지만**, 화면은 단색 도형 위주라 실제 매장과 거리가 멀다. 실제 설치 현장은 매장마다 인테리어·조명·기기 색이 모두 다르다.

그래서 **시뮬레이터의 모델과 로직은 건드리지 않고 "룩"만 갈아끼우는 레이어**를 Unity 에디터 툴로 만들었다.
1. **Look Preset**: 조명·HDRI·재질·포스트 효과·배경 소품을 파일 하나로 묶은 프리셋. 켜고 끄면 원본이 정확히 복원된다.
2. **Reference Matcher**: 매장 사진 한 장으로 그 매장처럼 보이는 프리셋을 반자동 생성한다.
3. **Web Export + Live Link**: 만든 룩을 **돌아가는 웹 시뮬레이터에 1~2초 안에 실시간 반영**한다.
4. **Look Rules**: 어떤 레퍼런스로 만들어도 같은 실사 기준(조명 범위·반사율·재질 표준값·더티)을 지키는 스타일 가이드.

## 2. 전체 구조 (파이프라인)
```
[웹 시뮬레이터 three.js] --GLTFExporter--> cafesim_a100.glb --glTFast--> [Unity]
                                                                          |
     레퍼런스 사진 --> Reference Matcher --> Look Preset (+Look Rules)  <-- Look Panel(수동 조정)
                                                                          |
                                     Export / Live Link (look.json + 텍스처, live.json)
                                                                          v
[웹 시뮬레이터] LookLayer: 재질 번호 매핑 → 조명·재질·스티커·포스트 적용 (시뮬레이션은 계속 동작)
```

## 3. 단계별로 만든 것과 기술
### 3-1. 웹 장면 → Unity 가져오기
- 브라우저에서 three.js `GLTFExporter`로 시뮬레이터 장면을 glb로 내보내고, Unity에서 **glTFast**로 불러옴
- 문제: `InstancedMesh`(인스턴싱 메시) 때문에 glTFast 가져오기가 실패 → 내보낼 때 임시로 숨기고 시뮬레이터는 원상복구
- 좌표계: three.js와 glTF→Unity 변환 차이로 **x축만 반전**(웹 ↔ Unity 변환 함수로 통일)

### 3-2. Look Preset 시스템 (ScriptableObject)
- 프리셋 = 데이터 파일: HDRI 스카이(주변광), 키·필·림·스포트·포인트 조명, 실시간 반사 프로브, Post Processing v2 프로필, 재질 세트, 카메라 앵글, 접지 그림자, 배경 소품, 레퍼런스 사진, 웹 보정값
- **비파괴 적용**: 적용 전 RenderSettings·조명 세기·카메라·재질을 기억 → 추가 오브젝트는 `HideFlags.DontSave` 리그 아래 → 끄면 통째로 제거·복원
- **씬 저장 보호**: `EditorSceneManager.sceneSaving` 훅에서 잠시 원본으로 되돌렸다 저장 후 다시 적용
- `Resources/Looks`에 파일만 넣으면 목록에 자동 추가(쉐이더팩처럼)
- 라이트맵 베이크 없이 **실시간 조명 + 실시간 반사 프로브**만 사용

### 3-3. 고퀄 재질 세트 (원본 무수정)
- glb 원본 재질 34개를 **복제**해서 색·금속성·거칠기로 자동 분류(스테인리스·유리·석재·광택 도장·인쇄 스티커·발광 등)
- 분류 결과를 텍스트로 남겨 검증(`Materials/HQ/_분류결과.txt`)
- 키오스크 화면: 웹에선 HTML(iframe)이 3D 위에 겹쳐 보이는 "투명 구멍"이라, Unity에선 **뷰어를 Edge 헤드리스로 캡처**해 화면 텍스처로 사용

### 3-4. 레퍼런스 맞춤 프리셋 (화이트 라운지 / 다크 라운지)
- 사진을 분석해 조명 방향·색온도·재질을 맞추고 카메라 앵글을 재현
- CC0 텍스처: Poly Haven(HDRI·오크·회벽), ambientCG(대리석)
- **세로 홈(플루팅) 노멀맵을 코드로 생성**, 어두운 본체 위 인쇄는 **텍스처 색 반전**(채도 높은 아이콘은 원래 색 유지)

### 3-5. Reference Matcher (반자동 프리셋 생성)
1. 사진 위에 부위(벽·바닥·상판·하부장·기계별) 영역을 드래그로 지정, 재질 종류 선택
2. 영역 색 **중앙값** 추출(하이라이트에 덜 휘둘림) → Look Rules로 **실제 반사율 범위(0.04~0.85)로 제한**
3. 재질 종류에 색 적용: 원목·대리석은 **결(밝기 변화)은 유지하고 색만 재매핑**, 테라조는 **절차 생성**
4. 벽 좌/우 밝기 차이로 **주 조명 방향 결정**
5. **톤 자동 보정 루프**: 렌더 → 측정(밝기 중앙값, 10~90% 밝기 폭, 채도, 따뜻함) → 포스트 값 보정을 반복, 오차를 숫자로 표시 (예: 0.801 → 0.030)
   - 보정은 규칙 범위 안에서만(노출 ±0.5 등) → 시작 조명의 그림자·대비가 살아 있게
   - 프리셋을 바꾼 직후 주변광(SH)이 갱신될 때까지 **에디터 프레임을 기다렸다** 측정
- 재질 번호 매핑, 같은 순서 번호 프리셋 구분(파일 경로로 식별), 생성 중 에셋 재임포트로 설정이 날아가는 문제(저장 순서) 등을 해결

### 3-6. 레트로 디테일: 더티·스티커·포스터 (모델 무수정)
- **Weathering**: 재질의 현재 색(텍스처×색)을 한 장으로 구우면서 Perlin/fBm 노이즈로 얼룩·세로로 흘러내린 자국·아래쪽 오염·긁힘, 하부장은 **페인트가 벗겨져 나무가 드러나는 마스크**
- **Dressing**: 스티커(흰 칼선·원/둥근 사각형/별·5x7 픽셀 폰트 글자)와 포스터(바랜 종이·큰 도형·망점·제목)를 **코드로 그려서**(저작권 문제 없음) 기계 면·하부장·벽에 겹치지 않게 배치하는 얇은 판
- **Contact Shadows**: Built-in RP엔 접촉 그림자가 없어서, 기계 밑·벽 닿는 곳·하부장 밑에 가장자리가 흐린 반투명 판으로 "떠 보임"을 제거

### 3-7. 웹 시뮬레이터에 적용 (LookLayer)
- **Stage.js 무수정**: `renderer.render`를 가로채 EffectComposer(GTAO·UnrealBloom·OutputPass·색보정/비네트 셰이더)로 그림
- **재질 번호 매핑**: Unity는 `렌더러 이름(Node-N) → glb 노드 → 메시 → 재질 번호`, 웹은 같은 `GLTFExporter` 플러그인(`writeMaterialAsync`) 순서로 같은 번호를 찾음 → 34개 색까지 일치 검증
- 텍스처 좌표 차이(glTF 방식 → flipY 끔), "텍스처 없음"도 전달(단색 페인트로 바꾼 재질)
- 키오스크는 **실제 HTML 화면 유지**(재질 목록에서 제외)
- 웹 밝기 보정: three.js 환경맵은 확산+반사가 함께 들어가 Unity보다 밝음 → **같은 앵글에서 영역별 밝기를 측정해 보정값을 맞춤**, 룩별 "웹 시뮬레이터 보정"(환경광·조명·노출)
- 사용자 **밝기 슬라이더**(-2~+2 EV, 브라우저에 기억)

### 3-8. 실시간 연동 (Live Link)
- Unity: `ObjectChangeEvents`(인스펙터 수정) + `AssetPostprocessor`(새로 만들기·복제·삭제)로 변화 감지 → 0.5초 모아서 **바뀐 것만 내보내기**, 고른 프리셋은 `live.json`에 기록
- 웹: 개발 모드에서 1초마다 `live.json` 확인 → 같은 룩 다시 적용(HDRI 캐시, 텍스처 버전 쿼리)
- 서버 추가 없이 **파일로 통신**(같은 PC), 배포 시엔 Export 한 번

### 3-9. Look Rules (일관성)
- 조명 시작점·톤 보정 범위·AO/비네트/접지 그림자, **알베도 범위**, 재질별 거칠기/금속성 표준값, 부위별 더티 기본값, 웹 보정 기본값
- 규칙 파일을 복제하면 다른 스타일 기준(예: 인더스트리얼)으로 같은 사진도 일관되게 생성

### 3-10. AI(Claude)와 MCP를 활용한 개발 방식
- **MCP for Unity**(HTTP 서버)를 통해 에디터를 자동화: 컴파일·콘솔 확인·메뉴 실행·C# 코드 실행·렌더 캡처
- 웹은 **브라우저 자동화**(페이지 JS 실행, 캔버스 캡처)로 시뮬레이터에 룩을 적용하며 확인
- 매 단계 **같은 앵글 Unity/웹 비교 이미지와 영역별 밝기 수치**로 검증하는 루프

## 5. 해결한 문제들 (면접에서 이야기하기 좋은 것)
1. **원본 무수정 원칙**: 프리셋·재질·소품 모두 복제/임시 오브젝트 → 끄면 100% 원본. 씬 저장 시 자동 원복
2. **재질 번호 일치**: 서로 다른 엔진(Unity/three.js)에서 같은 재질을 찾는 방법을 glb 구조로 해결, 색 비교로 검증
3. **"떠 보임"과 "컴컴함"**: 접지 그림자 추가 + 장면 크기(0.8m)에 비해 과한 AO를 찾아 조정
4. **사진 색 ≠ 재질 색**: 사진엔 조명이 섞여 있음 → 반사율 범위 제한 + 톤 보정 범위 제한(Look Rules)
5. **엔진 간 밝기 차이**: 같은 앵글 측정으로 웹 보정 계수 산출, 룩별 미세 보정
6. **에디터 비동기 이슈**: 주변광 갱신 지연, 에셋 재임포트로 설정 유실, 메모리의 옛 프리셋 참조 등 → 프레임 대기·저장 순서·강제 재임포트로 해결
7. **환경 제약**: exFAT 드라이브(심볼릭 링크·git 소유권) → 임시 복사본 + 정션, safe.directory

## 6. 결과물
- 프리셋 4종(화이트 라운지·다크 라운지·레트로 분식·빈티지 그린) + 원본
- 레퍼런스 대비 톤 오차: 레트로 0.801→0.030(초기 버전), 규칙 적용 후 0.589→0.372 / 빈티지 0.69→0.50
- 코드 규모: Unity C# 17개 + 웹 JS 1개, 약 2,800줄
- 저장소: unity-render-presets(main), cafesim 포크(look-presets)

## 9. 이력서 문구 예시
- "Unity 에디터 룩 프리셋 툴 개발: 원본 수정 없이 조명·재질·포스트·더티를 프리셋으로 교체하고, 레퍼런스 사진에서 프리셋을 반자동 생성(영역 색 추출·반사율 제한·톤 자동 보정)"
- "Unity ↔ three.js 룩 파이프라인: glTF 기반 재질 매핑과 JSON 룩 포맷으로 동작 중인 웹 시뮬레이터에 실시간(Live Link) 적용"
